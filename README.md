KrashCode — терминальный ИИ-агент для работы с кодом. Читает и изменяет файлы, ищет по проекту,
запускает команды и стримит ответы в интерактивном TUI.

Построен на TypeScript, React/Ink и Vercel AI SDK. Поддерживает OpenAI, Anthropic, Google и
OpenAI-совместимые провайдеры (OpenRouter, Ollama и т.д.).

## Возможности

- потоковые ответы от ИИ в реальном времени, с выводом reasoning
- чтение, создание и точечное редактирование файлов (с защитой от выхода за пределы проекта)
- поиск по именам и содержимому файлов (glob/grep)
- запуск shell-команд с таймаутом и обрезкой вывода
- режимы `normal` / `accept` / `plan` и подтверждение вызовов инструментов
- долговременная память проекта (`/memory`) — заметки живут между сессиями
- сжатие контекста (`/compact`), учёт токенов и оценка стоимости (`/usage`)
- переключение моделей и провайдеров (OpenAI, Anthropic, Google, OpenRouter, локальные)
- сохранение и восстановление сессий (`-c`, `-r`, `/sessions`)
- автодетект проверок проекта (lint/typecheck/test) после правок
- оригинальная эмблема KrashCode и читаемый двухцветный заголовок
- нейтральная тема System и шесть акцентных тем с предпросмотром и сохранением
- настраиваемые анимации: полные, спокойные, выключенные
- адаптивный TUI, история ввода, Unicode-редактор и автодополнение команд

## Требования

- Node.js 22+
- npm

## Установка

```sh
git clone https://github.com/your-username/KrashCode.git
cd KrashCode
npm install
npm run build
npm link
```

## Настройка

```sh
# OpenAI
krashcode setup openai --model gpt-4o

# Anthropic
krashcode setup anthropic --model claude-sonnet-4-20250514

# Google
krashcode setup google --model gemini-2.5-flash

# OpenRouter
krashcode setup openrouter --model openai/gpt-4o --key-env OPENROUTER_API_KEY

# Локальный сервер (Ollama)
krashcode setup custom --model llama3 --base-url http://localhost:11434/v1
```

При `setup` без `--key-env` ключ спрашивается скрытым вводом и сохраняется в `~/.krashcode/auth.json`
(права `0600`). Иначе берётся из переменной окружения (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY` и т.д.)
или из указанной в `--key-env`. Сменить ключ отдельно: `krashcode key <provider>`.

## Запуск

```sh
krashcode              # запустить TUI
krashcode -c           # продолжить последнюю сессию в этом каталоге
krashcode -r <id>      # возобновить сессию по id
krashcode --model <m>  # запуститься с выбранной моделью
krashcode config       # показать конфиг
krashcode sessions     # показать сессии
```

## Команды внутри TUI

| Команда | Действие |
|---------|----------|
| `/theme [name]` | Выбрать тему с предпросмотром или применить по имени |
| `/motion [full\|reduced\|off]` | Настроить анимации |
| `/model [name]` | Сменить модель |
| `/mode [normal\|accept\|plan]` | Сменить режим (или `Shift+Tab` — цикл) |
| `/sessions` | Возобновить сохранённую сессию |
| `/compact` | Сжать старый контекст в резюме |
| `/memory [set <текст>\|clear]` | Заметки проекта между сессиями |
| `/bypass` | Вкл/выкл подтверждения вызовов |
| `/usage` | Токены и оценка стоимости |
| `/config` | Показать конфиг |
| `/clear` | Новая сессия |
| `/help` · `/exit` | Помощь / выход |
| `Esc` | Прервать запрос · очистить ввод · выйти (если пусто) |
| `Ctrl+C` | Выйти с сохранением сессии |

## Оформление и анимации

`/theme` открывает выбор: **System** (родные цвета терминала, по умолчанию), **Ember** (янтарь), **Ocean** (бирюзовый), **Forest**
(зелёный), **Violet** (лаванда), **Paper** (акценты для светлого терминала) и **Mono** (монохромная).
Стрелки показывают тему в живом предпросмотре; Enter сохраняет выбор, Esc возвращает
предыдущую тему. Можно сразу ввести `/theme ocean`. Настройка сохраняется в
`config.json` и восстанавливается при следующем запуске. Уже напечатанная история
терминала не перекрашивается; новая тема применяется к живому интерфейсу и новым сообщениям.

`/motion` открывает настройку анимаций:

- `full` — индикаторы работы и потоковый курсор; название и эмблема не мигают;
- `reduced` — только спокойный индикатор выполнения, без декоративного движения;
- `off` — статичные состояния. Счётчик времени продолжает показывать время работы.

Анимации также отключаются при перенаправлении вывода, в CI, при `TERM=dumb`,
`NO_COLOR`, `INK_SCREEN_READER=true` или `KRASHCODE_REDUCED_MOTION=1`.
Эмблема и название статичны — постоянной перерисовки на экране ожидания нет.
В узких или низких окнах большая эмблема скрывается, а название остаётся читаемым;
исходный рисунок в файле `logo` не изменяется.

### Совместимость цветов

Интерфейс вдохновлён спокойной типографикой [OpenCode](https://github.com/anomalyco/opencode):
компактное строчное блочное название, нейтральный текст и поле ввода без лишних рамок.
Оригинальная эмблема KrashCode сохранена; для размещения обрезаются только пустые поля.

Заливок фона нет: приложение сохраняет фон терминала и использует его основной цвет текста.
Это избегает цветных полос при переносах, смене темы и прокрутке. Paper не меняет фон —
используйте её в светлом терминале. Сохранённая ранее тема не сбрасывается: для нового
нейтрального стиля выполните `/theme system`.

Определяются 16 цветов, 256 цветов и truecolor. Если терминал сообщает неверные возможности,
можно задать режим вручную (примеры для bash/zsh):

```sh
KRASHCODE_COLOR=ansi krashcode       # надёжные базовые цвета
KRASHCODE_COLOR=256 krashcode        # 256 цветов
KRASHCODE_COLOR=truecolor krashcode  # RGB, если терминал поддерживает
NO_COLOR=1 krashcode                # полностью без ANSI-стилей
```

`NO_COLOR`, `TERM=dumb` и перенаправление вывода отключают ANSI-стили даже при `FORCE_COLOR`.
Обычный курсор ввода подчёркнут, без инверсии цвета и фона.

### Управление вводом

- ↑/↓ в пустом поле — последние 50 отправленных запросов и команд текущего запуска;
- Home/End или Ctrl+A/Ctrl+E — начало/конец строки;
- Ctrl+U / Ctrl+K — удалить текст до/после курсора;
- Tab — дополнить команду; Enter — отправить или выбрать;
- в списках работают PgUp/PgDn, Home/End и переход по первой латинской букве;
- длинный текст прокручивается вокруг курсора; вставленные переносы видны как `↵`
  и передаются агенту без потери абзацев.

## Режимы

- `normal` — файловые правки и команды спрашивают подтверждение
- `accept` — правки `write`/`edit` применяются автоматически (bash всё равно спрашивает)
- `plan` — только чтение: изменяющие инструменты заблокированы, агент возвращает план

## Встроенные инструменты

| Инструмент | Описание |
|------------|----------|
| `read` | Чтение файла с нумерацией строк |
| `write` | Создание/перезапись файла |
| `edit` | Точечная замена фрагмента в файле |
| `bash` | Запуск shell-команды (с `background: true` — фоново, без ожидания) |
| `bash_output` | Чтение вывода фоновых команд, их список и остановка (`kill`) |
| `glob` | Поиск файлов по паттерну |
| `grep` | Поиск по содержимому файлов (regex) |
| `memory` | Чтение/обновление долговременных заметок проекта |

Долгие команды (dev-сервер, watcher, сборка) запускаются с `background: true` и не
блокируют агента: он читает их вывод через `bash_output`, а при выходе фоновые процессы
гасятся автоматически.
